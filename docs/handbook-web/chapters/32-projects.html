Part 10 · Project & meeting management

Projects

A project is the folder every meeting lives in. Create one with full metadata, build its member roster, delegate authority with roles, dress it with a colour and icon, and retire it when its work is done.

Two doors into one project

A project name appears in two places in the left sidebar, and they do different things. Knowing which is which saves a lot of hunting for controls that aren't where you expect.

Clicking a project under the Projects heading in the sidebar takes you to that project's meeting list — a clean view of its cards, with a small ⚙ shortcut in the title row. That view holds no administration. All of it — create, edit metadata, members, guests, delete — lives on the separate Manage projects page, reached from the Manage projects sidebar item. The rule of thumb: the sidebar project link means “go to its meetings”; the Manage projects page means “administer it.” Creating a project just opens a personal folder where you become its leader and owner — it grants no power over anyone else's projects.

Internal-only

Manage projects, Guest manager and My Files appear in the sidebar only for internal staff accounts. A guest never sees them. The server enforces the same gate, so the page is genuinely staff-only, not merely hidden.

Create a project with full metadata

  1. Click New project — at the top of the Manage projects page, in the empty state, or in the sidebar footer. All three open the same modal, titled Create new project.
  2. Fill in the Name (required) and optionally a cover image, project code, client, location, branch/office, phase, project type and description.
  3. Click Save. The app first creates the project by name, then saves the extra fields in a second step.
  4. On success the modal closes and you land in the new project's detail — ready to add members, the natural next step.
  5. If the create call itself fails, the modal stays open with everything you typed so you can retry; the toast reads “Couldn't create the project — check your network and try again.”

→ The new project is created with you as its leader and owner. There is only one create path — full metadata in one modal — so no half-configured folders.

Note

If the name saves but the extra details don't, you still land in the project, with the toast “Project created, but saving extra details failed — press Edit to retry.” Nothing you typed for the name is lost; re-enter the rest via Edit project.

Who can create

Any internal (non-guest) account may create a project. Creating one grants no cross-project power — it simply opens your own folder.

Search

The Search projects… box matches against the name, code, client and location — so a project code or client name finds the folder fast.

Reading the detail page
  1. 1 All projects — the back link (chevron-left) that returns you to the grouped list.
  2. 2 Hero — the cover image (or a letter initial), the project name with its icon, the stage pill and the code.
  3. 3 Cosmetic accents — a palette (“Đổi màu dự án” / change project colour) and a smiley (“Gán biểu tượng dự án” / assign project icon). Any member may set these; hidden for invitee-only folders.
  4. 4 Edit project and View meetings → — edit metadata (managers only) and jump to this project's meeting list.
  5. 5 Details section — Client, Location, Branch / office, Project type, Created, Leader, the description, and the read-only Leading department.
  6. 6 Members, Project guests and the collapsible Danger zone follow — each a native expand/collapse section.

Edit a project's metadata

  1. Open the project on the Manage projects page so its detail is showing.
  2. In the hero, click Edit project (pencil). It appears only for managers, and never on an invitee-only folder.
  3. The same field modal opens, now titled Edit project, pre-filled with the current values.
  4. Adjust any field and click Save.
  5. On success the modal closes and the detail refreshes.

→ Your changes are saved in one call (unlike create, which is two steps). The stage pill, code and Details grid update to match.

Note

If the save fails, the modal stays open — your edits aren't silently lost — and an alert reads “Save failed — …”. Fix the cause (usually network or permission) and Save again.

Read-only banner

If you were only invited into a project for one meeting, its detail shows the banner “You're invited to this project — view only” and no edit, members or guest controls appear.

Build the member roster

  1. In the project detail, expand the Members section. Members are grouped by department, each as a full row: avatar, name, title chip and role badge.
  2. Click Add member to open the staff picker, select one or more internal colleagues, and confirm. The roster reloads with them added.
  3. To remove someone, click the ✕ on their row and confirm “Remove {name} from the project?”. The leader (owner) can't be removed — their row has no remove action.
  4. Leadership can promote a participant with Make co-operator (shield), or demote one with Remove co-operator.
  5. The leading-division head (or an admin) can hand over leadership with Assign project leader (crown), confirming “Make {name} the new project leader?”.
  6. Use Add guest (next to Add member) to jump straight to the Project guests section's issue form.

→ The roster reflects exactly who may see the whole folder. Roles drive what each person can do; the next table spells them out.

Note

Only internal colleagues can be added — the picker is drawn from the staff directory. If a member add is rejected, the alert reads “Couldn't add member (internal emails only).”

Host-only

A plain participant sees the roster read-only: no Add, no Remove, no promote/demote. The promote and assign-leader buttons appear only for the relevant authority tier.

Note

The role badge (Leader / Co-operator / Participant), the org-authority badge (Division admin) and the title chip are three separate things. A title or being a department head never locks the Make co-operator or Assign project leader buttons — authority and project role are independent axes. Only the current leader's row is fixed: the system refuses to re-role the owner.

Server-enforced

Every one of these checks is enforced by the server, not just hidden in the UI. The buttons you see reflect what the server will actually allow for your account.

Set a project colour & icon

  1. On a project tile (or in the detail hero), click the palette button — tooltip “Đổi màu dự án” (change project colour).
  2. Pick a colour from the menu; choose Default to clear it. The tile and its sidebar dot tint immediately, with no list flash.
  3. Click the smiley button — tooltip “Gán biểu tượng dự án” (assign project icon) — to pick an emoji from the project presets; choose the clear option to remove it.
  4. The colour and icon appear on the project's tile, its sidebar entry, and on every meeting card inside it.

→ The folder gets a glanceable accent that flows through to its meeting cards. Any member may set these — they're cosmetic, exempt from the owner-only guard.

Note

If a cosmetic save fails, the toast reads “Không lưu được màu/biểu tượng dự án” (couldn't save the project's colour/icon). The accent simply isn't applied; nothing else changes.

Not for invitees

The palette and emoji buttons are hidden on an invitee-only folder — there's nothing there for a guest department to restyle.

Delete a project

  1. Open the project detail and expand the Danger zone section (collapsed by default). It appears only for leadership — leader, leading-division head, or admin.
  2. Read the hint: “Can only be deleted when it has no meetings.”
  3. Click Delete project (trash icon) and confirm “Delete project "{name}"? This cannot be undone.”.
  4. On success the detail closes and a toast reads “Project "{name}" deleted.”
  5. If the project still has meetings, the deletion is refused with the alert “Delete all meetings in the project before deleting it.” — use View meetings → to go clean them up first.

→ A project can only be deleted once it's empty, so its meeting history is never silently destroyed. The action is permanent.

Note

A co-operator never sees the Danger zone — only true leadership (leader / head / admin) can delete. An invitee-only folder never shows it either.

If it won't delete

Any other failure shows “Couldn't delete the project.” — usually a network blip; try again.

Project administration fixes

No Manage projects item in the sidebar — You're signed in as a guest (external) account.

Project administration is internal-staff only. Sign in with your staff account. → 19.2

Can see a project but no Edit / Add member buttons — You're a plain participant, or only invited into the folder for one meeting.

Ask the project leader or a co-operator to grant you a managing role. Invitee folders are always view-only. → 19.6

Read-only banner on a project's detail — Another department invited you in for a single meeting.

“You're invited to this project — view only.” You can see it but not administer it; that's expected. → 19.6

Can't make someone a co-operator — You're a co-operator, not leadership.

Only the leader, leading-division head or admin can delegate roles. Ask one of them. → 19.7

Add member rejected — You tried to add a non-internal email.

“Couldn't add member (internal emails only).” Only staff accounts can be project members; issue a guest ID for external people instead. → 19.6

Delete refused — The project still contains meetings.

“Delete all meetings in the project before deleting it.” Open View meetings →, remove them, then delete. → 19.10

Project list empty slot says couldn't load — The list fetch failed (network / server).

“Couldn't load — check your network connection.” Click Retry; your existing list is kept, not blanked. → 19.9

Extra details didn't save after create — The metadata save (second step) failed.

“Project created, but saving extra details failed — press Edit to retry.” Open Edit project and re-enter the rest. → 19.4

Note

Cosmetic colour/icon changes and member edits each refresh just the one item in place — the list never flashes. If an action seems to do nothing, check for a toast at the bottom of the screen; that's where these messages appear.
