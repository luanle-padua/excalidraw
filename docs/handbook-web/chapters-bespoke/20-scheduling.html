Scheduling a meeting

One form does two jobs. It can spin up a room and drop you straight into it, or it can plant a meeting on a future date, stamp it with an agenda, name a host, and quietly invite everyone who needs to be there. This chapter walks the whole form, field by field, exactly as the app draws it.

Two modes, one form

Create & join or Create & invite — the same panel serves both, and the only difference is whether the meeting starts now or sits on a date you choose.

When you press the project's New meeting button, the form opens in now mode: the meeting is created with status live and you are taken straight into the room the moment you submit. There is no date picker — a now-meeting starts the instant it is born.

When you open the form to Schedule — by clicking a day in the calendar column on the right — it opens in schedule mode. Now you get a date, a time, and a duration. The meeting is created with status scheduled; you are not taken into a room. Instead it appears in every invitee's Invited / Upcoming list, ready for its hour.

Everything else — title, agenda, roles, people — is identical between the two. The form deliberately mirrors the edit form: what you can set when you create a meeting is exactly what you can change later.

now vs. schedule The same panel, two lifecycles: now → live → you enter; schedule → scheduled → Upcoming list.
Host-only

The New meeting and Schedule entry points only appear to project owners and co-operators. A plain participant browsing the project will not see them — they receive meetings through invitations, covered in the next chapter.

Opening the form

  1. To start a meeting right now, open a project and press New meeting at the top of the meetings column. The form opens in now mode, bound to that project.
  2. To plan one ahead, look at the calendar in the right-hand column and click the day you want. The form opens in schedule mode with that date pre-filled.
  3. When you open Schedule from the calendar with no project selected, the top of the form shows a project Select a project dropdown — you must pick one before you can submit.
  4. The title field is focused automatically, so you can begin typing the moment the panel appears.
  5. Changed your mind? Press the back arrow in the top-left of the panel (its label is Leave) to close without creating anything.

→ The right-hand panel now shows the meeting form — a back arrow and a New meeting or Schedule heading at the top, four stacked zones below, and a single primary button at the foot.

Host-only

If you manage several projects, the schedule-mode project dropdown lists every project you can create meetings in. The chosen project decides which guest list appears later — the form never silently files a meeting under an arbitrary project.

Title, date, time, duration

  1. Type a Meeting title in the large field at the top. This is the only required field — the submit button stays disabled until it has text.
  2. In schedule mode, set the Date & time. Click the date box to pop the native date picker; if the meeting is unscheduled you may leave the date blank.
  3. Pick a start time from the dropdown — it offers every half-hour from midnight to 23:30. The time defaults to 09:00 (or the time you clicked in the calendar).
  4. Set the Duration (min) in the number box; it defaults to 60 and steps in fives. The quiet min suffix sits beside it.
  5. In now mode there is no date row at all — the meeting starts immediately, so date, time, and duration simply do not appear.

→ A titled meeting with, in schedule mode, a concrete start moment and length. Leaving the date empty in schedule mode creates the meeting with no scheduled time — it shows as Not scheduled and you can set a time later via Reschedule.

Note

The time dropdown is click-only — there is no free-typing of arbitrary minutes. Choose the nearest half-hour, then fine-tune the meeting later if you need an odd start time.

Every dropdown carries a blank — entry at the top, so each tag is optional — leave it blank and the meeting simply has no value for that field. The four vocabularies are the same set you see when editing a meeting or filtering the project list.

Host-only

These tags are how a busy project stays legible: Confidentiality in particular signals whether external guests belong in the room. They are labels, not locks — set them honestly so co-operators reading the project list can tell a Confidential design review from a Client-shared presentation at a glance.

Naming the host and co-host

  1. Pick the Host from the dropdown. It defaults to you, the organizer — every internal person you have invited also appears as a candidate.
  2. Optionally pick a Co-host. The dropdown opens on — None —; the list is the same internal candidates minus whoever is currently host.
  3. Only internal invitees can host or co-host — guests never appear in these dropdowns. To make someone a host candidate, invite them in the People zone first.
  4. If you choose a host who is already the co-host, the form clears the co-host automatically so the two roles can't collide.
  5. Note the two switch rows — Waiting room for guests and Record the meeting. Both are labelled (coming soon) and are switched off and disabled; they are placeholders, not yet-enforced policies.

→ The meeting carries a designated host (you by default) and, optionally, a pre-assigned co-host whose invitation arrives already stamped with the co-host role.

Note

If you invite someone, name them host, then remove them from the People list, the form keeps the now-orphaned name selectable rather than silently snapping back — so the host you chose never quietly changes underneath you.

Host-only

Pre-naming a host matters most for meetings you schedule but won't run yourself. The named host can start the room in your place, and the usual host away → acting host fallback still applies if neither of you arrives.

Inviting the room

  1. Search internal colleagues in the Search by name / department… box — it matches name, email, division, and job title — then click a result to add them.
  2. Prefer a checklist? Press Members to open the Select members picker, tick everyone you need, and confirm with Done.
  3. Invite external contacts from Project guests: search and click a name. Guests must already be issued in the guest manager — there is no free-typed email box here.
  4. Each person you add appears in the grid at the top of the zone, clustered by division with their avatar; press the remove control to drop anyone.
  5. When at least one internal person is selected, a checkbox Also grant project access (internal only) appears, ticked by default — leave it on to give colleagues standing access to the project, not just this one meeting.

→ On submit, everyone selected is invited to the meeting; the pre-named co-host's invite carries the co-host role, and ticked internal colleagues are added to the project.

Note

The internal search shows the first 50 matches and the guest search the first 30; narrow your query if someone is missing. When a search finds nobody you'll see No one found (internal) or No project guests yet — issue one in the guest manager (guests).

Host-only

The guest list is strictly per-project: only guests issued to this project appear, and they are invited by their project login, never a raw email. That is what keeps each department's external contacts walled off from the others.

Create & join, or Create & invite

In now mode the foot button reads Create & join. Press it and the meeting is created live and you are taken straight into the room.

In schedule mode the button reads Create & invite. The meeting is created scheduled; you stay on the dashboard and it surfaces in everyone's Upcoming list.

The button is disabled until the title has text, and again while the create is in flight, so a double-press can't make two meetings. If the server refuses the create — a permissions or connection problem — the form stays open and shows Save failed — check your permission (organizer only) or the meeting state. rather than pretending it worked.

Scheduling troubleshooting

The create button is greyed out and won't click. — The Meeting title is empty, or a create is already running.

Type a title. The button enables the moment the title has non-blank text; if you just pressed it, wait for the in-flight create to finish. → 20.6

In schedule mode from the calendar, I can't submit. — No project is bound — the form opened with no project context.

Pick a project in the Select a project dropdown at the top of the form, then submit. → 20.2

Submitting shows “Save failed — check your permission…”. — The server refused the create — you're not the organizer for that action, or the worker is unreachable.

Confirm you own or co-operate the project and that you're online, then try again. The form keeps your entries. → 20.6

A colleague I want as host isn't in the Host dropdown. — Only internal invitees are host candidates; the person isn't yet invited.

Add them in the People zone first — they then appear as a host and co-host candidate. → 20.5

The Project guests list is empty. — This project has no guests issued, or your search matched none.

Clear the search; if it's still empty, issue a guest ID in the guest manager first — guests can't be free-typed here. → 20.6

The Waiting room / Record switches won't turn on. — Both are marked (coming soon) and are intentionally disabled.

Nothing to do — they're placeholders for a future release, not active policies. → 20.5

Note

Leaving the date blank in schedule mode is not an error — the meeting is created with no scheduled time and shows as Not scheduled. Give it a time later with Reschedule.
