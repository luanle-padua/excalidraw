## 1. State machine vòng đời meeting (CHỐT + ENFORCE)

`scheduled → live → finished | cancelled` — một bộ giá trị duy nhất (migration `0013_status_canonical.sql`, client đọc tolerant qua `components/mcm/meetingStatus.ts`).

- **Lifecycle chỉ đi qua ACTION**: Start / End-for-all / Huỷ / Khôi phục / Xoá — `status` đã bị **bỏ khỏi metadata editor** (trước đây dropdown sửa tay phá được invariant).
- **Start gate** (`WaitingForStart` + `startGateAtom` trong Collab): mở link meeting `scheduled` → nội bộ thấy nút **Bắt đầu** (luật acting-host: nội bộ nào cũng start được khi host vắng), khách **poll 5s** tới khi live thì tự vào; meeting huỷ → thông báo.
- **`finished` = immutable TOÀN PHẦN**: server 409 mọi PATCH (mọi field) + **mọi đường vào đều read-only review** (kể cả link thô/resume — bỏ carve-out cũ "review chỉ từ folder tile"; chính carve-out này gây lỗi 409 anh gặp khi vào lại phòng đã End).
- **Dời lịch / Huỷ / Khôi phục / Xoá vĩnh viễn** (organizer): trong detail panel; xoá CHỈ khi đã cancelled, cascade đủ R2 + file + invitee + participant + note (vá lỗ orphan của admin delete).
- **Resume bug fix**: meeting finished/cancelled không hiện "Tiếp tục cuộc họp" nữa; End-for-all tự clear lastMeeting.
- **MeetingDueNotice**: toast góc phải khi meeting `scheduled` tới giờ (cửa sổ −10/+5 phút, poll 60s, đổi title tab 🔔) → đề nghị Vào họp.

## 2. Quyền — identity = email đã verify, server enforce (Worker)

- **Tạo meeting NGUYÊN TỬ**: `POST /v1/meetings` nhận đủ payload (status/giờ/thời lượng/topic/metadata/**host & co-host**/waiting_room/recording_enabled); `organizer_email`/`host_email` **stamp từ JWT** — client không tự khai; status lúc sinh chỉ `scheduled|live`; ON CONFLICT chỉ fill NULL (không cướp được ownership/room_key của meeting có sẵn).
- **PATCH guard**: content = organizer-only (403); transition validate + **internal-only** + chống race (conditional UPDATE `WHERE status IS ?` → 409 khi 2 transition đua); cancel/restore = organizer.
- **`canSeeMeeting` = invited-only (CHỐT MỚI)**: organizer/host ∪ invitee active ∪ project_member ∪ admin — **bỏ internal-allow**; nội bộ không được mời cũng không thấy/không join được. Người mời phải tự thấy meeting (chặn tự mời mình vào).
- **Host election theo EMAIL** (`hostSocketIdAtom` rework): match `host_email`/`organizer_email` từ registry (tên hiển thị chỉ còn fallback legacy — hết bug trùng tên); host vắng → nội bộ đầu tiên = acting host; **phòng toàn khách = HOSTLESS** (trước đây fallback joinedAt trao quyền kick/mute/End cho khách!); organizer vào là quyền tự trả về.
- **Project model (chiều)**: `POST /v1/projects` tự insert owner-member từ JWT (fix **"tạo project xong biến mất"** — GET theo membership mà POST không tạo member row; backfill `0014`); `PATCH /v1/projects` **owner-only** (đóng audit finding #4); **`projectAccess` 3 mức** full/partial/null — *nội bộ được mời 1 meeting của dự án (phòng ban khác)* → thấy project badge **"Được mời"**, mở vào CHỈ thấy meeting được mời/đã tham gia (chốt **B+** thay B trong host-and-scheduling.md); khách ngoài vẫn không bao giờ thấy folder.
- Guest mời tay → **tự đồng bộ vào bảng `client`** (mọi user + admin thấy chung một danh bạ).

## 5. CHIỀU MUỘN — Chốt production data + thực thi P0 (1 worker-pass + 3 team agents song song)

Buổi bàn production data structure kết thúc bằng **4 quyết định anh Luân duyệt** (ghi đầu `production-data-plan.md`): ① admin **compliance access** (mở nội dung mọi meeting read-only, audit BẮT BUỘC, user không được báo); ② **"Tài liệu của tôi"** (tủ cá nhân, copy-snapshot vào meeting); ③ nguyên tắc **"thấy meeting = thấy toàn bộ dữ liệu"** + 2 ngoại lệ (recording P5, **Confidential = invitee-only ENFORCE**); ④ **AI summary-first** (End → auto-summary → D1 query được; transcript chi tiết E2E blob; scope AI = scope người hỏi).

**Cách tổ chức:** em viết TOÀN BỘ phần Worker trước (1 người sở hữu `index.ts` — tránh 3 agent giẫm nhau), rồi phóng 3 agent client song song (~37'/agent), anchor i18n/SCSS tách vùng riêng từng agent.

**Server (P0 + 4 quyết định):**
- **`worker/migrate.mjs`** — migration runner chung local/remote (`node migrate.mjs [--remote|--status]`), track bằng bảng `schema_version` (0015); từ nay KHÔNG `d1 execute --file` tay. Local 16/16 applied.
- `0015_p0_parity`: schema_version + tombstone `deleted_meeting` + `meeting.ai_summary(+_at)` + seed `internal_domains`; `0016_user_files`: bảng `user_file`.
- **P0.2**: worker đọc `system_settings.internal_domains` (cache 60s/isolate, refresh trong JWT middleware, fallback hardcode) — setting admin sửa giờ là THẬT.
- **Confidential enforce**: `canSeeMeeting` + list project-meetings + `/v1/me/meetings` đều lọc — Confidential chỉ organizer/host/invitee thấy, project member thường KHÔNG (cả card lẫn vào phòng).
- **P0.5 tombstone**: cascade ghi `deleted_meeting`; mọi PUT scenes/files/chats/library/transcripts + POST register → **410 Gone** — meeting xoá là xoá hẳn, client còn mở phòng không "hồi sinh" được.
- **P0.3**: `PUT/GET /v1/transcripts/:roomId` (E2E như chats, sau roomGate); `POST /v1/meetings/:id/summary` → cột D1 (route riêng vì meeting đã finished khi summary về — summary là derived data, không phải content edit).
- **My Files API**: `/v1/me/files` CRUD, R2 `userfiles/<email>/<fileId>` server-readable + bảng index, owner-scoped qua JWT, max 50MB.
- **P0.6**: `DELETE /v1/projects/:id` (owner chỉ khi project TRỐNG — meeting phải đi đúng lifecycle; admin force-cascade), GET/POST/DELETE `project_member` (chặn xoá owner CUỐI), admin projects list + counts.
- **Compliance route** `POST /v1/admin/meetings/:id/open`: audit row `admin.open_content` ghi TRƯỚC khi trả room_key — audit fail = từ chối access (khác logAudit best-effort).

Verify live cả 2 chiều.
